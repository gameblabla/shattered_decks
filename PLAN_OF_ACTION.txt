  Work from commit 886b3da, which is intentionally marked BROKEN/WIP. First repair the static top-view cache,

  ### Why the current renderer is still slow

  The board is only 5×4—20 cells—so scanning the cells to classify the mesh is not the principal problem.
  Concentrate on:

  - build_board_projected() projects 52 board/slab points every frame, normally performing two fixed-point divisions
    per point.

  - The general moving-camera path repeatedly sets up and walks cell edges per scanline.
  - cfx_draw_board_span_tilted() performs integer division inside its texture-run loop.
  - The trapezoid path still contains variable 255 / span divisions.
  - render_board() clears the entire 61,440-byte framebuffer.
  - Walls and the board call fb_damage_all(), leading to dense/full presentation.
  - The current i386 fillers already pack four pixels per store, so an assembly rewrite is not automatically the
    largest available gain.

  The latest valid moving-turn capture measured roughly 71–111 ms step plus 22 ms present. The older 43–50 ms
  numbers came from a materially different state and must not be used as the current baseline.

  ### Phase 2: remove divisions from raster hot loops

  Start here because it is low-risk and the 386SX integer divider is expensive.

  In cfx_draw_board_span_tilted():

  - Replace the positive and negative “pixels until next 8-pixel texture boundary” divisions with a 64-byte
    ceil(distance / magnitude) lookup for distances and magnitudes 1–8.

  - Any magnitude at least 8 produces a one-pixel run.
  - Handle step == 0 and -128 explicitly.
  - Confirm the compiler emits no idiv in the span loop.

  In the trapezoid scanline path:

  - Replace variable 255 / denom and ceil(255 / denom) operations with exact lookup results for denominators 1–256.
  - Preserve the current signed int8_t wrapping and truncation exactly.
  - Do not silently substitute the approximate reciprocal helper where it changes pixels.

  Gate: framebuffer output must be byte-identical for every benchmark pose. Keep the change only if it wins
  repeatably.

  ### Phase 3: optimize projection before rewriting fillers

  Refactor build_board_projected() so the regular board grid does not perform complete dot products independently
  for all 52 points.

  Precompute, per camera:

  - X-axis contributions for the six board columns;
  - Z-axis contributions for the five board rows;
  - Y contributions for FIELD_Y and FIELD_THICK;
  - contributions for camera-space X, Y and Z separately.

  Compose each point using additions in the same arithmetic order as vdot() so results remain exact. Derive slab-
  bottom points from the same contribution tables instead of transforming them again.

  Then measure the projection divides separately. If they remain significant:

  - compute or approximate reciprocal Z once per vertex and use it for both projected coordinates;
  - correct the estimated quotient to reproduce the existing toward-zero result exactly;
  - avoid 64-bit/libgcc arithmetic in the hot path;
  - compare every projected point and final framebuffer against the reference path.

  Do not use a faster approximate projection unless all scripted camera states remain pixel-identical.

  ### Phase 4: replace the generic moving mesh walker

  Create an FM TOWNS-specialized 5×4 planar-grid path, retaining the generic implementation as a reference/fallback.

  The new path should:

  - build each unique projected grid edge once;
  - process scanlines outermost;
  - maintain active edge state incrementally;
  - share boundaries between adjacent cells;
  - avoid reconstructing four quad edges for every cell;
  - emit the same per-cell affine U/V spans as the existing renderer;
  - select the two board textures directly without generic atlas/tile dispatch;
  - use exact reciprocal/step tables rather than per-span division.

  Do not replace the board with one globally projective-textured polygon: that changes the current piecewise-affine
  pixels. A different image is not an optimization.

  Gate this phase against the generic reference at all turn poses, clipping cases, and both turn directions.
